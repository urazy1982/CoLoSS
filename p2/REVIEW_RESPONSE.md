Mutation checks confirm that the new tests fail when each v1 defect is put back. # Smoke-test revision after the first GPU run (package v4)

The first GPU smoke run failed `top1_agreement 0.964 < 0.98`. The v3 check compared the bf16 unmerged path with an fp32 dense reference over the whole model. That gap mixes two things: bf16 rounding of the **base** model, which would occur with no adapters at all, and the error of the adapter composition, which is what the check is meant to catch. On four short prompts (~167 positions), 0.964 is 6 flipped positions, typically near-ties on prompt tokens.

v4 separates the two:
1. **`layer_exactness` (new, hard):** for every wrapped layer, in fp32 on random inputs, the factored composition must equal the dense W0 + ΣΔW within relative error 1e-4. This tests the composition arithmetic directly.
2. **`top1_agreement` (revised, hard):** the bf16-versus-fp32 agreement with all six adapters active may be at most 0.02 below the same agreement for the bare base model, with an absolute floor of 0.90.

This is not a loosening that could hide an adapter defect. If the base model alone agrees about 1.0 with its fp32 reference and the composition 0.964, v4 still fails. The smoke test is a numerical preflight, not a pre-registered endpoint, and the pre-registration was not yet frozen. The failed v3 log is kept and reported.
